## 2. Root Cause Analysis & Prescribed Fixes for Common Errors

### Error 1: Multi-Sentence Dialogue Truncation (`trace_004`)
- **Symptom:** In a multi-sentence dialogue monologue (e.g. "We need to go. Now!"), only the first sentence is present in the synthesized audio stem.
- **Primary Source Cause:** `KPipeline.__call__` uses `split_pattern=r'\n+'` or punctuation regex to yield a generator of `(graphemes, phonemes, audio)` tuples for streaming. An early `return` inside `for _, _, audio in generator:` terminates on chunk 0, discarding all subsequent chunks.
- **Prescribed Fix:**
  ```python
  chunks = [audio for _, _, audio in generator if len(audio) > 0]
  if not chunks:
      raise RuntimeError("Kokoro generated 0 audio frames")
  full_audio = np.concatenate(chunks)
  ```

### Error 2: Zero-Chunk Pause / Non-Lexical Punctuation Crash (`trace_005`)
- **Symptom:** Dialogue segments containing only ellipses (`"..."`), question marks (`"?"`), or pause brackets crash with `ValueError: need at least one array to concatenate` or produce a corrupted 0-byte WAV.
- **Primary Source Cause:** `phonemizer` strips punctuation and non-alphanumeric characters, resulting in an empty token stream and 0 yielded audio arrays.
- **Prescribed Fix:**
  ```python
  if not text or not re.search(r'\w', text):
      silent_audio = np.zeros(int(max(0.5, target_duration_s) * self.sample_rate), dtype=np.int16)
      sf.write(str(output_path), silent_audio, self.sample_rate, subtype="PCM_16")
      return round(len(silent_audio) / float(self.sample_rate), 3)
  ```

### Error 3: Windows PermissionError / File Lock Contention (`trace_006`)
- **Symptom:** `PermissionError: [WinError 32] The process cannot access the file because it is being used by another process` during Director targeted retries or audio scrubbing.
- **Primary Source Cause:** On Windows OS, open file handles held by media streaming bridges or previous read locks block in-place overwrites with `sf.write(output_path)`.
- **Prescribed Fix:** Atomic write pattern using sibling temporary file and `os.replace`:
  ```python
  temp_wav = output_path.with_suffix(".tmp.wav")
  sf.write(str(temp_wav), full_audio, self.sample_rate, subtype="PCM_16")
  os.replace(temp_wav, output_path)
  ```

### Error 4: Missing `espeak-ng` / CUDA OOM / System Library Failure (`inv_005`, `inv_006`)
- **Symptom:** `RuntimeError: espeak not installed on your system` or `torch.cuda.OutOfMemoryError` crashing the entire pipeline.
- **Primary Source Cause:** Kokoro non-English phonemizers depend on external C library `espeak-ng`. On machines without `espeak-ng` or with low VRAM, initialization throws.
- **Prescribed Fix:** Catch `(ImportError, RuntimeError, OSError, Exception)` and gracefully route synthesis to `EdgeTTSAdapter` using `spec.edge_female_voice` or `spec.edge_male_voice` from `resolve_language(target_lang)`.

### Error 5: 32-Bit Float vs 16-Bit PCM Incompatibility (`inv_005`)
- **Symptom:** Downstream Python stdlib `wave.open()` fails with `wave.Error: unknown format: 3` when reading 32-bit float WAVs generated by default `sf.write`.
- **Primary Source Cause:** Python `wave` module only supports standard PCM (Format Tag 1, 16-bit integer).
- **Prescribed Fix:** Always specify `subtype="PCM_16"` in `sf.write`.
